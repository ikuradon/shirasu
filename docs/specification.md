# 仕様

## 受信と配送

受信機はgpsdのu-bloxストリームからQZQSMを復号します。
通常・優先・最優先の通報と、訓練／試験・訂正・取消／解除を区別して本文へ表示します。
復号基準の受信日時と原電文を保持し、本文末尾へNMEAを付けます。

投稿はNostr kind 1です。署名済みイベントをSQLiteへ保存してからリレーへ送信します。
再送時は本文・画像URL・ALT・ID・署名を作り直しません。
配送期限は既定15分、重複抑制は同じ通報を最後に受信してから24時間です。
設定項目は`config/config.py.example`を参照してください。

画像付き投稿には本文と同じURLを持つ`imeta`タグを付け、`m`にMIME、`alt`に
種別・JST日時・訓練／取消等の説明を記録します。[NIP-92](https://github.com/nostr-protocol/nips/blob/master/92.md)
クライアントによって画像表示・ALTの利用状況は異なります。

## 分割通報の集約

| 通報 | 単位と待ち時間 | 追加・訂正・取消 |
| --- | --- | --- |
| 台風 | 投稿アカウント・台風番号・発表日時・情報種別・通報区分ごと。画像有効時は既定180秒後に受信済みの地点をまとめる | 後着地点は既知の全地点で追加更新。訂正・取消は未送信の集約を抑制する |
| 南海トラフ | 画像設定に関係なくページを保存し、全文が揃えば即時に1投稿 | 既定180秒で未完了なら断片を載せず受信状況を1回通知。後着完成時は全文を追加。訂正・取消は古い組立を抑制する |

集約途中の入力と締切もSQLiteへ保存します。重複受信で締切は延びません。
待ち時間は`SHIRASU_TYPHOON_WAIT_SECONDS`・`SHIRASU_NANKAI_WAIT_SECONDS`で1〜300秒に設定でき、
配送の再送期限より短くする必要があります。署名済み・公開済みの投稿は変更しません。

## 画像URL

受信機はURLの署名だけを行い、描画や画像取得をしません。画像サービスは入力から画像を再生成でき、
Blob/R2や画像用DBを必要としません。署名URLの有効期限はなく、公開後は誰でも取得できます。

```text
/vN/<key-id>/<payload>.<signature>.png
/v5/<key-id>/<payload>.<signature>.w1.webp
```

`payload`は下記のJSONをキー順固定・空白なしのUTF-8で直列化し、zlib圧縮後、
paddingなしbase64urlにしたものです。`t`は最古の受信Unixミリ秒、各offsetはそこからの差です。

```json
{"r":[[0,"$QZQSM,..."],[1000,"$QZQSM,..."]],"t":1700000000000}
```

レコードは受信日時・NMEA順で並べます。上限は32電文、受信時刻差24時間、
圧縮後4,096 bytes・展開後8,192 bytes・パス8,192文字です。
HMAC-SHA256は版・key-id・payloadを認証し、WebPではさらに`w1`と`webp`を含む別の署名領域を使います。
署名確認後にサイズ上限付きで展開し、NMEAの構造とチェックサムも検証します。
詳細な正規化規則は共有プロトコル実装とそのテストが基準です。

`w1`は可逆WebP、quality 100・method 4・exact、Pillow 13.0.0／libwebp 1.6.0を固定します。
符号器を変える場合は別プロファイルを追加します。形式のネゴシエーションは行いません。

| HTTP | 動作 |
| --- | --- |
| `GET /healthz` | 鍵・固定アセット・符号器を検査。正常200、不備503。no-store |
| 署名パスの`GET` / `HEAD` | `image/png`または`image/webp`。実画像のSHA-256をETagに使用 |
| `If-None-Match`一致 | 304 |
| 不正入力 | 署名不正403、署名済みで復号不能400、描画環境不備503。queryは拒否 |

正常画像は`Cache-Control: public, max-age=31536000, immutable`と
`Vercel-CDN-Cache-Control: public, max-age=31536000`を返します。キャッシュキーはパス全体です。
エラーはキャッシュせず、同じWebP URLでPNGを代返しません。

## 描画版と対応範囲

描画版はURLの互換性を表し、Gitの配布タグとは別です。既存URLの画像・署名・復号結果を維持します。
通常ソースの配布はv1〜v4で、v5は検証済み候補パッケージで登録します。
作業版の変更を既存v5へ重ねず、公開時に出力の互換性を確認します。

| 版 | 専用表示 |
| --- | --- |
| v1 | 台風進路・震源。その他は要旨 |
| v2 | 海上警報・震度・津波の区域地図 |
| v3 | 気象・緊急地震速報・火山 |
| v4 | 気象の種別別配色 |
| v5 | 共通16:9配置、洪水・降灰・北西太平洋津波・対応するDCXの地図、南海トラフ見出しカード、取消カード、WebP |

v5は1920×1080で、左に地図、右に受信値を表示します。長い説明は投稿本文に置きます。
狭い対象では周辺地形が分かる縮尺を使い、拡大図の右下に底図と主図範囲だけのミニマップを置きます。
不足する区域・値を推測せず、全情報を表示できない場合は要旨またはトピック画像へ切り替えます。

- **震度**: 県単位の受信値を代表位置に置く。観測点や面的な震度分布ではない。
- **緊急地震速報**: 警報対象区域と通報全体の予測値を区別する。
- **洪水**: 予報区域コードに対応する河川区間を描く。市町村面・川全体・浸水範囲へ置き換えない。
- **降灰**: 市町村ごとの基点＋1〜6時間、降灰量、小さな噴石を保持する。未記載時間や分布・軌道を補わない。
- **北西太平洋津波**: 公式予測地点へ受信値を表示する。代表点を沿岸全体の分布にしない。
- **DCX**: 地点・範囲 → 対象区域 → トピックの順に、確認できる情報だけで選ぶ。[詳細](dcx.md)
- **南海トラフ**: 完成した全文と取消報に見出しカードを添える。未完了通知は本文のみ。

地理データの取得元・加工条件は[`vendor/`](../vendor/README.md)、入力の出典は
[`tests/fixtures/qzqsm/`](../tests/fixtures/qzqsm/README.md)に記録しています。
同梱サンプルや合成訓練例は最新の災害情報ではありません。

## 取消報

取消は解除・安全宣言とは区別し、以前の警報色・進路・予測値・震源印を再表示しません。
背景は①確認済み元報の明示参照、②取消報自身の有効な区域、③地図なしの順で選びます。
①はオフラインプレビュー専用です。QZQSMの番号・時刻・区域だけで元報を自動確定しません。

| 取消報の種類 | 自身の入力から使える背景 |
| --- | --- |
| 気象 | 取消の伝送条件を確認できる記録的短時間大雨（Ww=21）の区域のみ |
| 緊急地震速報・震度・津波 | 定義済みの区域コード |
| 洪水・降灰・火山 | 対応する河川区間・市町村・火山の固定位置 |
| 台風・震源・南海トラフ | 位置を推定せず地図なし |
| 北西太平洋津波・海上 | 当該取消形態が仕様で未定義 |

未知の区域や必要な境界の欠落があれば部分地図を残しません。元報参照を与えた場合も
情報種別・通報区分・時刻・固有コードの整合を検査しますが、元報との関係を証明するものではありません。
根拠: [IS-QZSS-DCR-017](https://qzss.go.jp/en/technical/download/pdf/ps-is-qzss/is-qzss-dcr-017.pdf)、
[QSSアプリケーションノート](https://qzss.go.jp/en/technical/download/dc-report/users-manual_ver1.pdf)。
