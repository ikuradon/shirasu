# 未公開地図の範囲計算の高速化

この計測後の地域投影・Path生成の再利用は[次の改善結果](geometry-reuse-performance.md)に記録します。

`5bec6af` の計測機能を基準に、未公開プレビューの地図で不要な範囲計算を省きました。
主図・ミニマップの表示範囲は従来どおり、受信した全対象と周辺の地理情報から先に決定します。
範囲の決め方、区域の頂点、投影、文字配置、画像形式は変更しません。

## 実測結果

Linux aarch64・論理4CPU、Python 3.12.16、Matplotlib 3.11.2、NumPy 2.5.4、
Pillow 13.0.0で計測しました。以下は再描画3回の中央値です。

| 入力 | 変更前 | 変更後 | 時間短縮 |
| --- | ---: | ---: | ---: |
| 緊急地震速報 | 16.966秒 | 6.238秒 | 63.2% |
| 震度情報 | 13.484秒 | 5.257秒 | 61.0% |
| 気象・複数区域 | 11.818秒 | 2.320秒 | 80.4% |
| 気象取消・明示元報参照 | 12.362秒 | 1.559秒 | 87.4% |
| 台風取消・明示元報参照 | 12.190秒 | 1.943秒 | 84.1% |

初回描画も緊急地震速報26.152秒→14.638秒、震度情報22.180秒→13.852秒、
複数区域の気象19.252秒→9.968秒、気象取消19.719秒→8.763秒、
台風取消19.583秒→9.229秒に短縮しました。初回にはアセット等の読み込みが残ります。
元報参照の取消はオフラインの明示参照例で、実受信の元報を自動照合するものではありません。

## 変更箇所

Matplotlibの通常の`Axes.add_patch`は、自動範囲調整が無効でもパッチの全区間を走査し、
自動範囲用の`dataLim`を更新します。以前の緊急地震速報のプロファイルでは、
`_update_patch_limits`が20回で累積14.60秒を占めていました（プロファイラー込み）。

`preview_wide_layout._axes`でのみ専用の`_FixedMapAxes`を使い、次の条件がすべて揃うときに
パッチ追加時の範囲計算を省略します。

- x・y両軸の自動範囲調整が無効。
- アスペクト比の調整対象が表示枠（`adjustable='box'`）。

`add_patch`そのものは継承したままなので、パッチ登録、座標変換、クリッピング、
削除、自動範囲計算の対象フラグは従来どおりです。通常のMatplotlibのAxesや公開版の
共有モジュールには変更を加えません。地図の主図・ミニマップ・取消背景に共通で適用します。

このAxesは固定表示範囲用です。将来自動範囲へ切り替える場合は、先に自動範囲を有効にし、
`relim()` → `autoscale_view()`の順で、省略していたパッチの範囲を再構築する必要があります。
一方の軸でも自動範囲が有効、または`adjustable='datalim'`の場合は通常の計算へ戻ります。

## 検証方法

変更前の`preview_wide_layout.py`をコミット`5bec6af`から抽出し、変更後と同じ画像用Docker、
依存ライブラリ、アセット、入力で直列に実行します。入力ごと・変更前後ごとに新しいプロセスと
空のMatplotlibフォントキャッシュを用意し、初回1回・再描画3回の中央値を比較します。
順序の偏りを減らすため、入力ごとに変更前／変更後の実行順を交互にしています。

時間はPNG生成までを含み、import、HTTP、CDNは含みません。OSのファイルキャッシュは
消去しません。表示範囲の記録は計測とは別の描画で行います。
全49入力のPNG照合は同一プロセス内で行い、この所要時間を初回の性能比較には使いません。
ローカルの計測であり、Vercelでの実応答時間ではありません。

計測記録とPNGは`dist/map-bounds/`に出力します。承認済みの`dist/preview/`と
前回計測の`dist/benchmark/`は比較基準として保持します。

確認できた結果は以下のとおりです。

- 全49入力（40ケース・46投稿の重複排除後）のPNGが、前回計測の基準PNGとバイト単位で一致。
- 代表5例は、初回・再描画3回・別途の範囲記録用描画のすべてで同じPNGを生成。
  変更前後で主図・ミニマップのx/y範囲・表示位置・表示方法の判定が一致。
- 公開版用45ファイル（コード・アセット・依存設定）が`5bec6af`とバイト単位で一致。
- 回帰テスト53件が成功。追加6件で範囲走査の省略・通常Axesの非変更・PNGとクリップの
  一致・自動範囲への復帰を確認し、既存テストで離島・日付変更線付近・降灰・河川・
  取消背景・公開版PNG・署名URLの維持を確認。追加テストをCIにも登録。

記録は`comparison.json`、`all-images/result.json`、`frozen-sources.json`、`tests.json`です。
抽出した変更前後のソース・SHA-256・差分と、比較に使った`verify_map_bounds.py`も保存します。

## 再描画の計測

既存の計測コマンドでも、同じ入力を再測定できます。

```sh
python -B scripts/benchmark_images.py --output dist/benchmark-map-bounds \
  --case eew --case seismic-intensity --case weather-many \
  --case weather-cancel-reference --case typhoon-cancel-reference \
  --warm-repeats 3 --encoding-repeats 1
```

画像用依存とプレビュー用アセットが必要です。既存出力は上書きしません。
形式変換は描画計測の後に行うため、変換時間は描画時間に含まれません。

## 次の候補

変更後の緊急地震速報をウォームアップ後にcProfileで確認すると、9.424秒の実行で
`_update_patch_limits`は20回・累積0.225ミリ秒となり、通常Axesの全区間走査は呼ばれていません。
地域の`_geometry`は16回・累積4.61秒残っています。プロファイラーの負荷を含む値なので、
上の通常計測の秒数とは直接比較しません。PNGは基準と一致しました。
記録は`profile-eew/profile.json`、`profile-eew/render.prof`、`profile-comparison.json`です。

区域データの投影・Path生成の再利用は別の改善として残します。今回は
キャッシュの上限や無効化規則を追加せず、地図の頂点や描画結果を保持しました。
