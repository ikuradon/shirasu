# 取消報の背景地図

2026-11-11時点。DCRの取消を、未公開プレビューで専用カードとして表示する。
取消は警報の解除とは別の情報形態であり、安全宣言に置き換えない。
取消前の警報色・進路・予測値・震源印は再表示しない。

## 背景の選択

1. 元通報との関係を利用者が外部の根拠で確認し、明示的に渡した参照が使える場合は、
   その参照を現在の未公開レンダラーで描いたときと同じ画角を背景に使う。
2. 取消報自身に独立して使用できる区域コードが揃っている場合は、その区域の背景を使う。
3. どちらも確認できない場合は地図なしの取消カードを使う。

どの場合も「取消」を主表示とする。背景には地形・境界・地名だけを残す。
第2段階は取消報に含まれる区域の参考表示であり、過去の投稿の特定や同一画角を意味しない。
一部の区域が不明、終端後にデータがある、必要な境界が欠ける場合、描ける部分だけを残さない。

## 元通報の自動照合は行わない

[IS-QZSS-DCR-017](https://qzss.go.jp/en/technical/download/pdf/ps-is-qzss/is-qzss-dcr-017.pdf)
の各データ形式には、元の通報を一意に指す共通IDがない。
送信側の更新単位に使う気象庁XMLのEventID・EditorialOffice等が、そのままQZQSMに
含まれるわけではない。Atは今回の情報の発表時刻で、取り消された元情報の発表時刻ではない。
地震の発生時刻は分単位、台風番号には年が含まれず、区域や位置も訂正・更新で変わり得るため、
受信履歴の「直近の1件」や番号・時刻の一致だけを確定照合として扱わない。

[QSSアプリケーションノート第1.0版（2020年）](https://qzss.go.jp/en/technical/download/dc-report/users-manual_ver1.pdf)
の39・43・46〜47ページにも、緊急地震速報・津波の過去情報との対応付けの制約がある。
取消時に同種の表示・履歴を消し、取消対象以外は後続の再受信で表示し直す例が記載されている。
これは元の1件を確実に選べる照合ルールを与えるものではない。

このため、現在の実装はQZQSM履歴から確定した元報を自動選択しない。
将来、公式の対応規則や外部の一意なイベント参照を確認できた場合に照合処理を追加できるが、
候補が一つしか見つからないことを根拠に「確認済み」と格上げしない。

## 明示的な元通報参照

オフラインの`--preview --cancel-reference original.json`、または
`render(records, cancel_reference=original_records)`で参照を渡せる。
指定は、利用者が元通報との関係を別途確認していることを前提とする。
プログラムによる基本チェックは、その関係を証明するものではない。

参照は同じ情報種別・通報区分・版の通常報または訂正報とし、発表時刻が取消報より後の
ものは採用しない。通常の描画が完全に成立して地図を持つことも必要である。
参照元も生データの全区域スロットを検証し、終端で隠れた区域を落とした画角を使わない。
気象は参照元も全項目Ww=21とし、台風番号・火山コード・降灰の速報／詳細区分は
両側の全電文について既知の矛盾がないことを確認する。
取消として未定義の型・未確認の気象副種別を、参照指定で有効化しない。
参照が合わなければ取消報自身の区域、地図なしの順に切り替える。

ここで再現するのは**現在の未公開レンダラーでの画角**であり、公開済みv1〜v4のPNGの
過去の画角を取得・再現する機能ではない。集約された元画像の画角を使う場合は、
元の集約全体を参照に渡す必要がある。任意の画像URLや外部画像は読み込まない。
参照はオフライン専用で、署名URLの既存形式・HTTP API・本番投稿の入力には追加しない。

## 取消報から使える区域

判定は`image_service/preview_cancel_scope.py`の`plan_scope()`で行う。
次表は取消電文内の固定コードから背景の範囲を決めるための対応であり、取消された
災害の存在・現在位置・被害範囲・元投稿との対応を保証するものではない。

| 種別 | 背景に使う受信フィールド | 制約 |
| --- | --- | --- |
| 気象 | WwとPl | 伝送条件で取消が確認できる記録的短時間大雨Ww=21のみ。全項目の区域を保持 |
| 緊急地震速報 | Plの区域ビット | 定義された1〜70のみ。予約ビットや「その他」を県へ推測変換しない |
| 震度 | 都道府県Pl | 全受信県。震度の数値やマーカーは描かない |
| 津波 | 津波予報区Pl | 定義済み区域のみ。「その他の津波予報区」は不可。高さ・到達時刻は描かない |
| 洪水 | 洪水予報区域Pl | 特定の河川区間のみ。「その他の河川」は不可。警戒色を描かない |
| 火山 | 火山Vo | 固定カタログの火山位置で範囲を決定。火口・警戒区域を推測しない |
| 降灰 | 市町村Pl | 全指定市町村。降灰量・予想時間・降灰分布を描かない |
| 震源・台風 | なし | 取り消された位置・予報点から背景範囲を推測しない |
| 南海トラフ地震 | なし | 固定区域の指定なし。既存の本文のみの投稿方針を維持 |
| 北西太平洋津波・海上 | なし | 仕様でIt=2が未定義。北西太平洋津波はIt=0、海上はIt=0/1のみ |

受信メッセージのMT・Dc・Vn・Rc・It・Atと復号済み属性を照合する。
区域配列は生の全スロットを読み、復号ライブラリが最初の全ゼロで配列を打ち切った後にも
値が残っていないか確認する。片側だけ0の対、未知コード、配列長や値の改変を許容しない。
範囲を決めるための関連項目（Ww、Lv、Es、降灰のHo/Dw2等）も検証するが、画像には載せない。
地理アセットの有無は描画段階で確認し、不足分を上位県や近隣区域へ置き換えない。

元通報参照にも共通の`validate_cancellation()`を適用する。確認済みの取消型であることと、
取消報自身に使える地理情報があることは分けて検証する。

## 根拠と再現データ

DCR-017（2026-09-02）の確認済みPDFのSHA-256は
`24bc3a2f62b22f0b46d9e01a2ed1cb61bc6c77b257567fc8588baf390a2ab84c`。
表4.1.2-5（緊急地震速報）、14（震度）、21（津波）、26（北西太平洋津波）、
30（火山）、35（降灰）、37〜38（気象）、43（洪水）、47（台風）、51（海上）を確認した。
区域の名称・コード表は固定したazarashi 0.17.1のDCR-017定義に一致させる。

既存の公開fixture3本（72・50・211フレーム）にはDCRの取消実受信例がない。
既存`weather-cancel`は大雨特別警報・土砂災害警戒情報・竜巻注意情報を含む気象例の
Itだけを変更した合成訓練例であり、Ww=21の取消運用を確認する例ではない。
この原本は保持し、背景を推測せず地図なしへ戻す確認に使う。
取消背景の追加例も合成訓練として明示し、実際に配信された取消と称さない。
元通報参照の例は明示的に対応を作った検証用の組であり、自動照合の成功例ではない。
