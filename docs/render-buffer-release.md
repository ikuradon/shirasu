# 未公開画像の描画バッファ解放

地域投影・Pathの再利用を追加した`8cd3ddc`を基準に、描画後のAggバッファを
循環参照のGC待ちから外します。対象は未公開プレビューの共通Figureだけです。
公開済みv1〜v4の描画コード・署名URL・PNG形式は変更しません。

## 実測結果

Linux aarch64・論理4CPU、Python 3.12.16、Matplotlib 3.11.2、NumPy 2.5.4、
Pillow 13.0.0で比較しました。どちらも通常のGCを有効にしたまま、明示的なGCは呼びません。

| 入力・連続回数 | 終了時RSS：変更前→後 | 残存RendererAgg：変更前→後 | 再描画中央値：変更前→後 |
| --- | ---: | ---: | ---: |
| 気象・20回 | 554.42 → 300.27 MiB | 20 → 0 | 1.127 → 1.104秒 |
| 緊急地震速報・4回 | 428.17 → 414.39 MiB | 4 → 0 | 3.109 → 3.145秒 |
| 南海トラフ・4回 | 120.77 → 96.02 MiB | 4 → 0 | 0.196 → 0.195秒 |
| 気象取消・元報参照・4回 | 339.22 → 296.95 MiB | 7 → 0 | 1.383 → 1.386秒 |

気象20回の終了時RSSは約46%減少し、ピークRSSも553.06→349.88 MiBになりました。
20回後もFigure・Canvasは各20個がGC待ちですが、重い描画バッファへの所有参照を外すため、
RendererAggは毎回の描画終了時に0個です。取消報では主図と元報参照用の一時図を測っています。

解放を含む描画時間の差は、代表4例で約−2.0〜+1.2%でした。気象のclear処理は
中央値11.09→12.86ミリ秒、緊急地震速報11.12→13.80ミリ秒、南海トラフ0.03→0.11ミリ秒、
取消報は複数図の合計20.48→42.56ミリ秒です。
以前の診断で試した毎回の完全GC（気象で約220ミリ秒追加）は導入していません。

初回は気象8.945→8.534秒、緊急地震速報15.810→16.193秒、南海トラフ0.317→0.316秒、
取消報8.846→8.927秒でした。速度向上を目的とした変更ではなく、ここでの時間差は
ローカル環境の測定値です。Vercelの実応答時間や速度改善の保証には使いません。

## 解放する参照

`preview_wide_layout.figure()`で作る専用Figureの`clear()`に処理を集約しました。

1. artistツリーを捨てる前に、入れ子を含むTextの`_renderer`参照を外します。
2. Agg canvasの`renderer`を外し、`_lastKey`をリセットします。
3. 通常の`Figure.clear()`を呼びます。

Canvasだけを外してもTextがバッファを保持します。両方の参照を外すことが必要です。
Canvas自体はFigureに接続したままなので、clear後の再描画・文字サイズ計測は通常どおり
新しいrendererを作れます。保存済みの図を検査する既存のテスト補助も利用できます。

通常の終了だけでなく、要旨表示への切替、DCXの次候補への切替、取消元報の一時図、
描画やPNG保存の例外で実行される既存のclearも対象になります。
Matplotlib全体への変更や、描画ごとの強制GCは加えていません。

Matplotlibの非公開キャッシュ属性を扱うため、固定している依存版で回帰テストを行い、
更新時にも同じテストを実行します。外部の呼び出し元がrendererを直接保持している場合や、
例外のtracebackがローカル変数を保持している間まで強制的に破棄するものではありません。

## 計測・検証方法

変更前の共通Figureモジュールを`8cd3ddc`から抽出し、その他のコード・アセット・依存は
同一にします。入力・変更前後ごとに別プロセスと空のフォントキャッシュを使用し、
比較順を入力ごとに入れ替えて直列実行します。OSのページキャッシュは消去しません。
気象は初回1回と再描画19回、他の代表例は初回1回と再描画3回です。

Figure・Canvas・取得した全RendererAggを弱参照で追跡します。描画時間はPNG生成と
clearを含み、import・ハッシュ照合・メモリやGC統計の取得は除外します。
RSSは`/proc/self/statm`、ピークRSSは`getrusage`で取得するため、カーネルの集計差もあり、
両者を厳密な同一時点の値としては扱いません。

全画像の確認は、49入力を同じプロセスで通常順・逆順の2周描画し、毎回バッファの解放、
基準PNGとのバイト一致、承認済みギャラリーの表示判定を確認します。
地域キャッシュの256項目・概算32 MiBの上限も併せて検査します。

98回すべてでPNGと表示判定が一致し、描画終了時のRendererAggは毎回0個でした。
承認済みギャラリーの40ケース・46投稿についても、2周分の172使用箇所を直接照合しています。
このプロセスのピークRSSは761.63 MiB、終了時RSSは755.31 MiBです。
複数種類の地理アセットを読み込むため、単一の気象画像20回の値とは区別します。
公開版用45ファイル（コード・アセット・依存設定）は`8cd3ddc`とバイト単位で一致しました。

回帰テスト114件はすべて成功しました。追加した9件ではGCを無効にし、`gc.collect()`の
呼び出しも禁止して、即時解放・文字計測だけで作られたrenderer・clear後の同一PNG再描画・
既存の図の検査補助・通常終了・要旨への切替・描画／保存の例外・南海トラフ・取消元報・
DCX候補切替を検証しています。通常のMatplotlib Figureの挙動が変わらないことも確認します。
既存テストで地図やラベル配置、公開版PNG・URL・配布物の分離も確認し、新規テストはCIへ追加しました。

記録は`dist/buffer-release/`の`comparison.json`、`all-images/result.json`、
`tests.json`、`frozen-sources.json`です。変更前後のソースと測定スクリプトも同じ場所へ
保存します。既存の`dist/preview/`と`dist/benchmark/`は比較基準として保持します。

## メモリ量の意味

この変更が解放するのは、図が所有していた描画バッファです。Figure・Canvasなどの
小さい循環参照は通常のGC、解放済み領域の再利用はallocatorに任せます。
元の地理アセット・フォント・上限付きの地域キャッシュも引き続き使います。
RendererAggが0個でも、プロセス全体のRSSが起動直後へ戻るとは限りません。
