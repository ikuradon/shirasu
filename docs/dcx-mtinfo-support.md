# DCX MTInfo 追加避難範囲の対応範囲

2026-11-11時点。自治体情報の追加楕円と指示を、投稿本文と未公開画像に対応させる。
稼働中の環境には未反映。既存の画像URL版と公開済み投稿は変更しない。

## 確認した仕様

[IS-QZSS-DCX-004（2026-05-29）](https://qzss.go.jp/en/technical/download/pdf/ps-is-qzss/is-qzss-dcx-004.pdf)
の英語版を確認した。取得したPDFのSHA-256は
`038dd2c130998514ae4001545cc9ce99905a8a94fe6b3a9ae1ee1018605f299e`。
以下のPDFページは、表紙を1ページとした位置を指す。

- §4.2.3.1（印刷15 / PDF22ページ）: A1の試験・発表・更新・解除。
- §4.2.3.9〜10（印刷21〜22 / PDF28〜29ページ）: 国内のA9=1、A10=0。
- §4.2.3.17（印刷37 / PDF44ページ）: 自治体情報はA17=0（B1）固定。
- §4.2.4.1.1〜8（印刷39〜42 / PDF46〜49ページ）: EX1、EX2〜EX7、国内Vn=1。
- §5.3.1（印刷56〜57 / PDF63〜64ページ）: 主楕円と追加楕円の送信例。
- §5.9（印刷73〜75 / PDF80〜82ページ）: 両楕円に共通するWGS84・ENUでの内外判定。
- §5.10（印刷76 / PDF83ページ）: A11とEX2〜EX7の併用、全ビット0による指示なし。

## 追加楕円の復号と描画

ビット位置はQZQSMペイロード先頭を0としたMSB順。以下のrawは符号なし整数。

| フィールド | 開始位置・幅 | 受信値の解釈 |
| --- | --- | --- |
| EX2 | 162・1 | 0: 追加範囲から離れる、1: 追加範囲へ向かう |
| EX3 | 163・17 | 中心緯度 `-90 + 180 * raw / (2**17 - 1)` 度 |
| EX4 | 180・17 | 中心経度 `45 + 180 * raw / (2**17 - 1)` 度 |
| EX5 | 197・5 | 半長軸、A14と同じ表（下記） |
| EX6 | 202・5 | 半短軸、A15と同じ表（下記） |
| EX7 | 207・7 | 方位 `-90 + 180 * raw / 128` 度 |
| Vn | 214・6 | 国内拡張の版。今回の対応は1 |

EX3は−90〜90度、EX4は45〜225度。復号ライブラリと一致する小数6桁で受け取り、
EX4が180度を超えた場合だけ360度を引く。日付変更線をまたぐ輪郭は連続に扱う。
EX7は−90〜88.59375度、**東を0度、北へ向かう回転を正**とする。
方位は小数5桁で照合する。北0度・時計回りには変換しない。

半軸のkm値は
`10**(log10(216.2) + raw * (log10(2500000) - log10(216.2)) / 31) / 1000`
を小数3桁に丸める。raw=0でも約0.216kmの範囲があり、欠測値ではない。
raw=31は2500km。半短軸が半長軸を超える値は採用しない。
仕様の計算例EX3=91522、EX4=68950、EX5=13、EX6=11、EX7=96は、
緯度35.687299度・経度139.689138度・半軸10.933kmと5.979km・方位45度となる。

§5.9は主楕円A12〜A16と追加楕円EX3〜EX7の両方に同じ内外判定を適用する。
追加楕円は独立した中心・半軸・方位を持つため、**追加楕円自身の中心を原点**にした
WGS84のENU座標で輪郭を求める。B3のように主楕円の座標系で中心移動・倍率・回転を
適用する形ではない。主楕円だけに適用されるB1/A18の細分値も追加楕円へ流用しない。
どちらかの範囲を投影できない場合、片方を省略した地図は作らない。

## 指示と対象区域の扱い

主楕円は通報対象の範囲。EX2=0の追加楕円は「離れる範囲」、EX2=1は「向かう範囲」として
区別する。範囲外や向かう先の安全性、移動経路、SNSの読者が範囲内にいることは推定しない。
A11も送信されている場合は、§5.10に従い追加指示と併せて参照する。
B3の重複時の主指示優先やC10=0の既定指示IC-A-03は、MTInfoに適用しない。

§4.2.4.1.1では、A12〜A16の全ビットが0の場合にEX1の市町村コードを対象区域として使う。
そのため「EX1の市町村境界＋追加楕円」も一つの地図候補として扱う。
主楕円がある場合はEX1を対象に加えず、主楕円がない場合だけ市町村境界へ切り替える。
市町村境界または追加楕円の一方が描けないとき、残りだけを表示して意味を変えない。
対象区域を確定できない場合はトピック表示へ戻し、受信した指示は本文に残す。

本文と画像は`dcx_instructions.mtinfo_evacuation()`で解釈を共有する。
対象はMTInfo、A2=111（日本）、A3=4、A9=1（国内ライブラリ）、A10=0（版#1）、
Vn=1、A17=0（B1）。生値の幅と復号値の一致も確認し、別版・未知の組合せを推測しない。
A1=0は訓練・試験、1は発表、2は更新、3は解除と区別する。
解除は通報に残る設定の説明とし、新しい避難行動を促す文にはしない。
日本語の補足は元の`str(report)`・A11・NMEAと分けて加え、元のreportを変更しない。
画像が無効・URL生成失敗・投影不可でも、適合する追加指示と楕円の受信値を本文に残す。

## 全ビット0とazarashi 0.17.1の差

仕様では**EX2を含むEX2〜EX7の全ビットが0**のときだけ追加指示なしとなる。
azarashi 0.17.1はEX3〜EX7だけを調べて`ignore_ex2_to_ex7`を立てる。
EX2=1、EX3〜EX7=0は、この差により復号済みの追加指示が欠ける。

この既知の組合せだけは生値から復元する。関連する復号済み属性がすべて未設定であることを
確認し、任意のignoreフラグ不一致や復号値の改変を許可する例外にはしない。
復元結果は中心南緯90度・東経45度、半軸0.216km、方位−90度であり、指示なしではない。
極域で地図に投影できなくても本文の「向かう」指示は保持する。
全ビット0の場合や未確認の版では、新しい日本語の指示を作らず受信テキストを残す。

## 再現用fixtureと限界

公開アーカイブ`tests/fixtures/qzqsm/qzqsm_dcx_260917.log`の0始まりフレーム163を元にする。
元ファイルのSHA-256は
`ff8887da0c458d72749b5d3e2526e695fcfa1e665c7a812cd67f00c0dc9e7726`。
出典URLと固定コミットは同ディレクトリの`manifest.json`に記録している。
記録の基準日時は2026-09-17 01:00:00 UTC、電文のA6/A7は同日02:30:00 UTC。
前者は年・日付の復元用であり、フレームごとの実受信時刻ではない。

元電文はVn=0の訓練であり、Vn=1の実受信例と見なさない。
既存の`dcx-mtinfo`原本と30ケースを保持したまま、次の3ケースを合成訓練例として追加する。
すべてA1=0（ビット24〜25）を強制し、Vn=1（214〜219）へ変更する。
時刻と災害種別、A11、EX1=1202（函館市）、追加楕円EX3〜EX7は保持する。
CRC-24Q（226〜249）とNMEAチェックサムを再計算する。

| ケース | Vnと訓練フラグ以外の変更 | 確認する内容 |
| --- | --- | --- |
| `dcx-mtinfo-leave` | なし、EX2=0を保持 | 通報対象の主楕円と離れる範囲 |
| `dcx-mtinfo-head` | EX2（162）=1 | 通報対象の主楕円と向かう範囲 |
| `dcx-mtinfo-area` | A12〜A16（80〜128）とA18（131〜145）=0、EX2（162）=1 | 函館市境界と向かう範囲の同時表示 |

元の追加楕円はEX3=95942、EX4=69687、EX5=3、EX6=3、EX7=37。
緯度41.757292度・経度140.701261度・両半軸0.535km・方位−37.96875度をそのまま使う。
合成例の目的は表示と処理の再現であり、当該自治体がこの指示を実際に配信したことや
指定先が安全であることを示さない。別途、生値の境界・版・解除・A11併用・投影失敗を検証する。
既存30ケースの入力・説明・メタデータは不変とし、画像回帰でも確認する。
