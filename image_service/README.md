# 署名付き QZQSM 画像サービス

受信機とは別に動かす、Python 3.12 / WSGI の画像レンダラーです。画像の入力は
`/v1/<key-id>/<JSON+zlib+base64url>.<HMAC-SHA256>.png` 、`/v2/...`、`/v3/...`、`/v4/...` に含まれます。
共有する `image_protocol.py` が署名とサイズを検証してから、azarashi で復号します。
現在時刻や外部 API は参照せず、URL に入っている受信時刻を復号の日付の基準にします。

PNG はメモリ内で生成して返します。Vercel Blob / R2 / データベースや PNG 保存先は不要です。
CDN のキャッシュが消えた場合は同じ入力から再生成します。Matplotlib のフォントキャッシュ
だけは一時ディレクトリを使用します。

## v1 の表示

- 台風: 同じ発表の中心位置を一枚の地図に集約します。実況は水色、推定・予報は白。
  時刻は JST で日付を併記し、年をまたぐ場合は年も表示します。予報円・暴風域は描きません。
- 震源情報: 受信した震央を地図に表示します。震度分布や揺れの到達範囲は推定しません。
- その他の DCR / DCX: 復号した通報のテキスト要旨を表示します。長文は画像内に抜粋である旨を明記します。
  未対応の地理データを警戒区域に見立てて描くことはしません。
- 訓練・試験、取消、DCX の解除を目立つ位置に表示します。取消の台風に予報経路は表示しません。
  未定義の位置・時刻・台風時刻分類はテキスト表示に切り替えます。

地図の範囲とラベル位置はデータから計算します。ラベルは実際の文字サイズで測り、
文字・引き出し線・予報経路が互いに重ならない配置を探索します。位置ラベルが入り切らない場合も要旨に
切り替えます。束ねられるのは同じ災害種別、発表日時、情報種別、通報区分の通報です。
異なる台風や同時刻の相反する位置を混ぜた入力は拒否します。入力は最大 32 通報です。

## オフライン画像ギャラリー

16種類・40ケースについて、公開済み版と作業版を横に並べるHTMLとPNGを一括生成します。
画像サービス用の依存関係と、[洪水の流路データ](#指定河川洪水予報のプレビュー)を準備した後、
リポジトリルートで次の1コマンドを実行します。

```sh
/tmp/shirasu-images-venv/bin/python -B scripts/render_gallery.py --output dist/gallery
```

`dist/gallery/index.html` をブラウザで開くと、種類・実受信／アーカイブ／合成・訓練区分・
発表／解除／取消で絞り込めます。検索では地名や「離島」「多数区域」も指定できます。
作業版には「地点・範囲／対象区域／トピック／地図／要旨」の選択結果と、切り替えた理由を
画像の下に表示します。未対応の通報バージョン、区域境界の不足、追加範囲の未対応、
配置上の制約、取消を区別し、理由別の絞り込みと件数確認もできます。
PNGを選ぶと原寸で表示し、出典・復号テキスト・入力JSONを各ケースから確認できます。
HTML・PNG・JSONはすべて同じ出力フォルダに収まり、サーバーやネット接続は必要ありません。

「投稿全体」と「画像のみ」を切り替えられます。新しく生成したギャラリーは投稿全体を
初期表示し、実際の配信で使う本文生成・集約処理から作った本文と、その投稿の電文に
対応する添付画像を一緒に表示します。台風の実況・予報は集約し、通常の複数気象電文は
配信処理と同じく別々の投稿として表示します。画像のみの比較で使う受信束を、そのまま
一つの投稿と見なすものではありません。本文の訓練・取消・解除の表現は変更しません。

条件は**画像機能が有効・保存済み履歴なし・入力順に待機時間内で受信**です。
公開ログの基準時刻は実受信間隔ではないため、入力を同じ仮想時刻で投入し、最後に
既定の集約待機時間180秒を進めます。既存の集約処理による重複除外や訂正・取消による
未投稿情報の抑制は反映しますが、実運用の受信時系列や既存の投稿履歴は再現しません。
南海トラフは完成した本文を1投稿にまとめ、作業版に見出しカードを添えます。
公開済み版の投稿欄は本文のみです。原NMEAも通常の本文として表示し、投稿本文の全文は
manifestの各ケースの`posts[].text`にも保存します。
本文に使う`record_indexes`と画像に使う`image_record_indexes`を分け、南海トラフの画像は代表の原電文1ページだけを使います。
画像のみ表示の入力は`preview_record_indexes`で記録し、旧ギャラリーで未記録の場合は全入力として比較します。

各画像の「代替テキスト（ALT）」から、読み上げ用の文面を確認できます。投稿本文の枠の外に
ある確認欄で、本文へ追記するものではありません。`img`の`alt`属性とmanifestの画像ごとの
`alt`へ同じ文面を保存し、実際の投稿の`imeta`でも共通の生成処理を使います。
情報種別、JSTの日時、訓練・試験／訂正／取消／解除を短く表し、DCRの発表日時とDCXの受信基準日時を
区別します。公開ログの基準日時は正確な受信時刻ではありません。取消・解除の古い数値や、
実際に描画するか不明な地理範囲は説明に補いません。
ALT未記録の旧ギャラリーでは、そのことを明示し、画像の従来の説明は維持します。

本文表示は、2026-11-11に確認した[nostterのソース](https://github.com/SnowCait/nostter/tree/78e22b7a7e79825290ee779a958a368eb90833f7)
の通常タイムラインを基準にしています。本番と共通の`with_image()`で画像URLの位置を決め、
その位置へローカルPNGを表示します。通常は説明 → 画像 → `---`・NMEAの順です。
NMEAだけの折り畳みや小さな別フォントは使わず、本文全体を同じ文字サイズで表示します。
長い投稿は本文・画像・NMEAを合わせた全体を最大30remで表示し、「もっと見る」で全体を展開、
「元に戻す」で閉じます。画像は最大幅`calc(100% - 1.5em)`・最大高さ`20em`を基準にします。
確認範囲は本文・画像の順序、改行、画像寸法、投稿全体の長文展開です。
根拠は[Content](https://github.com/SnowCait/nostter/blob/78e22b7a7e79825290ee779a958a368eb90833f7/web/src/lib/components/Content.svelte)、
[Foldable](https://github.com/SnowCait/nostter/blob/78e22b7a7e79825290ee779a958a368eb90833f7/web/src/lib/components/shared/Foldable.svelte)、
[Img](https://github.com/SnowCait/nostter/blob/78e22b7a7e79825290ee779a958a368eb90833f7/web/src/lib/components/content/Img.svelte)です。

添付PNGはローカルのプレビューです。署名URLやNostrイベントを作成・送信せず、
本番設定・秘密鍵・既存DBは読みません。取消の確認済み元報参照は本番の画像入力にないため、投稿全体の添付画像には
使用せず、画像のみモードで確認します。このため、元報参照付き取消例は両モードで
背景や表示理由が異なることがあります。

「画像の表示サイズ」で通常表示とSNS向けの画像幅320・360・430pxを切り替えられます。
初期表示は360pxです。投稿全体では投稿枠にも選んだ幅を適用します。画像そのものの表示幅を揃え、警報名・時刻・地図の記号・右欄を
拡大せずに読めるか確認します。表示幅は端末の画面幅とは別で、画面に収まらない場合は
画像・投稿部分を横スクロールできます。検索条件のリセットでも選んだ幅と表示モードを保持します。
既存PNGを等比縮小して表示し、原寸リンク・画像データ・描画結果の記録を維持します。
JavaScriptが無効な場合は欄の幅に合わせた通常表示になります。

比較する公開済み版は既定でv4です。稼働中のサービス設定とは独立しており、
`--published-version v1` などで変更できます。作業版のラベルを新しい公開バージョンとして
扱うことはありません。画像の「地図／要旨／トピック」は実際に保存された図から判定します。

```sh
python -B scripts/render_gallery.py --list
python -B scripts/render_gallery.py --output dist/gallery-ash --case ash-detail
python -B scripts/render_gallery.py --output dist/gallery-v1 --published-version v1 \
  --case typhoon-track --case marine
python -B scripts/render_gallery.py --output dist/preview --preview-only
```

`--preview-only` は作業版だけのギャラリーを生成します。公開版との比較を必要としない
デザイン確認に使用できます。理由はHTMLとJSONへ記録し、PNGや署名付きURLには加えません。

### 前回の作業版と比較する

保存済みギャラリーを`--baseline`に指定すると、前回の作業版と今回の作業版を並べます。
比較元は変更せず、別の新しい出力先を指定してください。

```sh
python -B scripts/render_gallery.py --baseline dist/preview --output /tmp/shirasu-next-preview
```

`--baseline`指定時は今回も作業版だけを生成します。`--published-version`とは併用できません。
「投稿全体」「画像のみ」のどちらでも前回／今回を確認でき、「変更あり」だけへの絞り込みも
可能です。比較状態と件数は表示モードに合わせて切り替え、表示理由フィルターは今回側を
対象とします。投稿数が変わった場合も、前回と今回の投稿をそれぞれの単位で表示します。

同じサンプルIDに対して、入力JSONのNMEA・復号基準時刻・並び順と、明示した取消元報の
全入力が一致した場合に出力を比較します。説明文や元ファイルのハッシュだけが変わっても、
実際の入力が同じなら比較できます。

| 比較状態 | 意味 |
| --- | --- |
| 変更あり | 同じ入力で、PNG・表示方法・表示理由、または投稿本文・構成・添付が変化 |
| 変更なし | 比較に必要な記録が揃い、記録された出力に変更なし |
| 入力が異なる | 元電文・日時・順序・取消元報参照等が異なり、同一入力として比較しない |
| 今回追加 | 比較元に同じサンプルIDがない |
| 比較できない | 前回の投稿記録がない、前回の描画エラーなどで必要な出力を比較できない |

PNGはファイル内容のSHA-256と寸法で比較します。表示理由は順序だけの違いを変更とせず、
記録なしと空の理由を区別します。投稿比較では画像有効・履歴・受信条件などの前提も確認します。
ALTだけが変わった場合も変更として検出し、両側に記録がある文面の変更と、片側だけに記録がある
「ALTの記録状態」の変更を区別します。PNGの変更とは別に表示します。
前回に投稿プレビューがない古いギャラリーでも、画像の比較は独立して使えます。
今回選ばなかった前回ケースは「今回の比較対象にない前回ケース」として残し、削除とは断定しません。

前回の検証済みPNG・入力JSON・投稿記録は出力先の`baseline/`へコピーするため、生成後は
比較元のフォルダを移動しても、出力先だけで表示できます。比較元のPNG欠落・ハッシュ不一致、
不正な相対パスやシンボリックリンクは生成前に検出します。Gitが使える作業ツリーでは、
コミットと未コミット変更の有無もmanifestへ記録します。

`--list` は描画依存や地図アセットなしでも、受信側の依存関係だけで動作します。
描画コマンドには上記の画像サービス用Pythonを使用してください。
既存の出力先は上書きしません。比較を残す場合は新しい出力先を指定します。
各セルの描画失敗は一覧に明示し、他の画像は生成を続け、終了コード1を返します。
必要なアセットがない場合は、出力フォルダを作る前に停止します。

Dockerでは、プレビュー用イメージを用意した後に次のコマンドで生成できます。

```sh
mkdir -p dist
docker run --rm --network none --volume "$PWD:/source:ro" --volume "$PWD/dist:/output" \
  --workdir /source shirasu-images:preview \
  python -B scripts/render_gallery.py --output /output/gallery
```

台風7時点、降灰5電文・18項目、複数区域の気象、解除・取消・離島、DCXを収録しています。
ケース定義は `scripts/gallery_catalog.py`、公開ログの出典は
[共通fixture](../tests/fixtures/qzqsm/README.md)にあります。
公開ログの日付基準は個別の受信時刻ではなく、年を持たない電文の復号用です。
元の公開ログと合成した訓練例を区別し、派生例の変更内容も一覧に記録します。
南海トラフには巨大地震注意・調査終了・取消の合成訓練例を収録しています。
本文の完成後に画像を添える条件は実配信と共通で、公開済み版には見出しカードの添付を行いません。

このツールはリポジトリから実行する確認用です。受信サービスやVercel配布パッケージには
含めません。本文・集約の再現にはメモリ内の新規DBを使い、秘密鍵・本番設定・既存の
配送DBは参照せず、署名・外部通信・投稿は行いません。
`manifest.json` に各入力の由来・出力PNGのハッシュ・描画結果を保存し、
公開ログのMITライセンスも出力フォルダへ同梱します。
作業版の `cases[].images.preview.decision` には `mode` と `reasons` を記録します。
各理由は固定の `code`、判断段階を表す `stage`、日本語の `message`、必要に応じた `detail` を持ちます。
正常な切替は描画エラーに数えません。理由が空なら対応した表示を直接使用し、項目がなければ
理由未記録として扱います。公開済み版や以前のmanifestの理由を推測で補うことはありません。
既知の制約だけを分類し、切替時の未知の例外は `unclassified_fallback` として例外原文を記録しません。
実際にPNGを生成できなかった場合は、従来どおり描画エラーと終了コード1で示します。

## 受信経過の投稿プレビュー

時間差で届く電文から、いつ何が投稿されるかをHTMLで確認します。既存の40ケースの
ギャラリーとは別に生成し、実際のcollector・Outbox・本文整形処理で4つの合成訓練シナリオを再生します。

| シナリオ | 受信経過と投稿 |
| --- | --- |
| 南海トラフ・後着完成 | 0秒に1ページ。180秒に未完了通知を本文のみで投稿。240〜270秒に残りが届き、270秒に全文と見出し画像を追加投稿 |
| 南海トラフ・途中の訂正 | 0・20秒に元報、60〜100秒に訂正報。100秒に訂正だけを投稿。130秒に来る古いページは抑制 |
| 南海トラフ・途中の取消 | 0・20秒に元報、60秒に取消を即時投稿。120秒に来る古いページは抑制 |
| 台風・追加受信 | 0・30秒に実況・予報、180秒に初回投稿。240〜270秒に追加予報、420秒に受信済み全6時点で追加更新 |

```sh
python -B scripts/render_timeline.py --list
python -B scripts/render_timeline.py --output dist/timeline
# 1シナリオだけを別の出力先へ生成
python -B scripts/render_timeline.py --output dist/timeline-late --scenario nankai-late
```

描画依存を入れた環境、または上記のプレビュー用コンテナで実行します。
Dockerでは、リポジトリを読み取り専用、出力先だけを書き込み可能で渡せます。

```sh
mkdir -p dist
docker run --rm --network none \
  --volume "$PWD:/source:ro" --volume "$PWD/dist:/output" --workdir /source \
  shirasu-images:preview python -B scripts/render_timeline.py --output /output/timeline
```

`dist/timeline/index.html`を開くと、受信・抑制・収集状況と投稿を経過時刻順に確認できます。
シナリオ選択、「投稿のある時点のみ」、投稿幅320・360・430px／通常に対応します。
本文とNMEAは実際の投稿と同じ内容で、画像URLの位置にローカルPNGを表示します。
長文は投稿全体を展開でき、ALTは投稿枠外で確認できます。JavaScriptなしでも全件を読めます。

時刻の`T+`は検証用の経過時間です。受信間隔は合成で、電文の復号に使う基準日時とは
別に記録します。履歴なし、収集待機180秒、配送は即時成功、待機中の投稿確認は1秒間隔という条件です。
同時刻では期限処理を先に行い、その後に各受信を処理します。新しく受け付けた電文は
投稿処理を起こしますが、重複や対象外の電文では起こしません。180秒ちょうどに南海トラフの
残りが揃う場合は、未完了通知と完成投稿が同じ仮想秒に出る場合もあります。
実リレーの遅延・失敗・再送や過去の実配信時刻を再現するものではありません。

結果は`manifest.json`に投稿全文・原入力番号・画像入力番号・経過時刻・収集数・PNGハッシュ・ALTを保存します。
各シナリオの入力、受信間隔、出典、合成変更点は`records/*.json`にも保存します。
設定・秘密鍵・既存DB・ネットワークは使わず、URL署名や実投稿は行いません。
既存の出力先は上書きせず、描画失敗はHTML・manifestに記録して終了コード1を返します。

`tests/test_timeline_publication.py`は、別の時計で毎秒実Serviceを動かし、投稿時刻・本文・NMEA・
画像入力・署名イベント・ALTの一致を確認します。画像付きのHTMLはPC・スマホ幅でも確認しています。

## 未公開画像のプレビュー

`--preview` で未公開の作業版を描画します。`--records` 専用で、`--version`・`--serve`
とは併用できません。指定しなければ従来どおりv1です。HTTP経路や署名対象の版は追加しません。
最初に、後述する[洪水の流路データの準備](#指定河川洪水予報のプレビュー)を行ってください。
流路データ本体はリポジトリに含めず、プレビューの固定アセットとしてローカルに生成します。

```sh
/tmp/shirasu-images-venv/bin/python -m image_service --preview \
  --records image_service/examples/northwest_pacific_tsunami.json --output /tmp/nwp-preview.png
```

北西太平洋津波は[気象庁の予測地点表](https://www.data.jma.go.jp/eqev/data/nwptac/forecastpoint.html)の
61地点を通報の沿岸コードに対応させます。表の図中番号は通報コードではないため、地点名と
沿岸ブロックを明示的に照合しています。受信した地点だけを表示し、震央・伝播経路・浸水範囲は描きません。

- 津波高は範囲、10m超、Huge、High、不明を区別します。国内の津波警報区分には置き換えません。
- 発表・到達予想の時刻はUTCです。翌日・翌月・翌年への繰り越しを保持し、`31:63` は
  「到達済み、または到達時刻不明」と表示します。実際の00:00を解除用の仮時刻とは扱いません。
- 同じ地点の矛盾、未知の地点・高さ、未対応の通報区分・情報種別、読める配置を作れない場合は、
  受信束全体を共通配置の要旨画像へ渡します。要旨が長い場合は抜粋である旨を明記します。
- 津波発生の可能性なし・その他の可能性情報は、活動中の地点予報に変換せず要旨画像で表示します。

`assets/preview/nwp_manifest.json` に出典・取得日・入力と加工後のハッシュを記録しています。
`scripts/prepare_nwp_assets.py` で再生成できます。実行時に地図や地点データを外部から取得しません。
同梱の北西太平洋津波サンプルは合成した訓練通報で、実際の災害情報ではありません。

未公開コードとアセットは通常の配布パッケージから除外します。ローカルDockerで確認する場合は、
新しい出力先に `scripts/prepare_image_service.py --include-preview dist/image-preview` を実行して
ビルドします。プレビューのパッケージは本番デプロイには使用しません。

### 共通配置の基準

気象・台風で確認した配置を、未公開プレビューの共通基準として固定しています。
描画は `preview_wide_layout.py` と各種別の `preview_wide_*.py` に分離し、公開済み描画の定数は変更しません。

- 1920×1080（16:9）。左上に題名・発表時刻・訓練／試験／訂正／取消を表示します。
- 右端24.5%の暗い情報欄に対象区域と受信した値をまとめます。長い防災文は投稿本文で読みます。
- ミニマップは情報欄に入れず、主地図の右下に配置します。地形・海岸線の底図と主図範囲の白枠だけを表示し、行政界・警報の輪郭や着色・進路・緯経線は重ねません。主図の対象やラベルが隠れない余白を確保します。
- 縮尺は全種類で可変です。狭い対象では、既存の気象庁の地理データから周辺の県・地方を選び、主図だけで場所を認識できる範囲まで表示します。離島は近くの島・諸島のまとまりを使い、所属県の遠い本土まで引きません。広域の対象や進路は全体が収まる範囲を保ちます。
- 地名は主図に薄く最大5個まで表示します。予報の値・記号・引き出し線・ミニマップに重なる地名は省きます。県・地方名は底図の位置説明であり、警報区域を追加するものではありません。
- 気象は右欄に区域名と情報種別を表示し、主図の警報区域は情報色の太い輪郭線で示します。黒には明るい縁取りを付け、複数種別も保持します。警報種別の説明は右欄にまとめ、地図に引き出し線は加えません。
- 台風は地図に受信した中心位置と日時、右欄に最新の実況／推定の値を表示します。予報だけの場合は実況がないことを明示します。
- 震度情報は県の代表位置に震度の四角いマーカーを置き、右欄は震度別の県名一覧にします。アルファベットの対応記号は使いません。地図の `5− / 5＋` は右欄の「5弱／5強」に対応し、「4未満」は数値に置き換えません。
- 震源・火山・緊急地震速報・海上警報・震度・津波・洪水・降灰・北西太平洋津波も同じ配置です。地図の地点・区域と右欄の対応が必要な場合だけ短い参照記号を使います。
- 降灰は市町村ごとに基点＋1〜＋6時間のマスを並べ、降灰量を色と文字で示します。小さな噴石は独立した段で示し、空欄相当の `—` は「この時間の記載なし」と明記します。連続した予報期間や降灰なしを推定しません。
- 津波は沿岸の代表位置、北西太平洋津波は公式予測地点のそばに受信した高さ・範囲・定性表現を直接表示します。右欄には地域名・高さ・到達状態／時刻を残し、国内の完全に同じ高さと到達情報の組だけをまとめます。解除・津波なしの通報は状態を主表示にし、通報に含まれる高さ・時刻と区別します。
- 洪水は単一区間なら地図に河川名を表示し、右欄の河川名・対象県・情報種別を分けます。複数区間は番号対応を維持し、元の予報区間や解除の意味を変えません。
- 緊急地震速報は警報対象区域を淡い共通色と細い輪郭で示し、細かな島々の輪郭が目立ちすぎるのを抑えます。予測震度は通報全体の値として右欄に表示し、地域ごとの震度分布にはしません。

DCRで地理情報がない通報、未知の値、全情報を読める配置にできない受信束は、同じ16:9の要旨表示にします。
DCXの未対応の地理情報は、下記の自動切替により本文を重複させないトピック画像にします。
南海トラフ以外の取消は右欄を持たない専用カードで、大きな「取消」、情報種別、取消報の発表日時、訓練区分を表示します。
背景は、別途確認して明示した元通報の画角 → 取消報自身の有効な固定区域 → 地図なし、の順です。
地形・県境・地名と右下の純粋なミニマップを暗く表示し、警報色・予測値・進路・震源印は描きません。
区域不明・境界欠落時には部分地図を残しません。取消を警報の解除や安全宣言に置き換えません。
元報の確定照合に使える共通IDがないため、受信履歴の最新報を自動で参照しません。
実装条件と種別別の対応範囲は[取消報の背景地図](../docs/cancellation-backgrounds.md)を参照してください。
長い要旨には抜粋と明記します。南海トラフは地図を使わない見出しカードとし、本文の全文は投稿に残します。
公開済みv1〜v4や署名付きURLにはこの配置を適用せず、新しい公開版は一括公開の段階で決めます。

南海トラフの見出しカードは、左に訓練区分・情報名・キーワード、右にJSTの発表日時と発表／訂正／取消を置きます。
調査中は淡い青、巨大地震警戒は赤、巨大地震注意は黄、調査終了・取消は灰色を使います。
本文・対象地域・ページ数を画像へ載せず、取消では古い注意・警戒の見出しを再表示しません。
全ページが揃った有効な本文と取消報だけを添付対象とし、未完了通知は本文のみ、後着で完成すれば全文と画像を追加投稿します。
画像には代表の原電文1ページを渡し、共有デコーダーの本文組立状態を変更せずにヘッダーを検証します。
公開済みv1〜v4への添付は無効です。新しい公開版の対応と同時に受信側の能力判定を有効にします。

```sh
python -B scripts/render_gallery.py --preview-only --output dist/nankai-preview \
  --case nankai-advisory --case nankai-ended --case nankai-cancel
```

元報との関係を外部の根拠で確認できた場合のみ、オフラインで参照を指定できます。
参照は現在の作業版での元通報の画角を再現し、過去の公開版PNGの画角は取得しません。

```sh
python -m image_service --preview --records cancellation.json \
  --cancel-reference confirmed-original.json --output cancellation.png
```

`--cancel-reference`は`--preview --records`専用です。画像URLやHTTP入力の拡張は行いません。
ギャラリーの`weather-cancel-area`・`weather-cancel-reference`・`weather-cancel-unknown`・
`typhoon-cancel-reference`は明示した合成訓練例です。参照例は元の入力JSONも保存し、
自動照合の成功例や実際に配信された取消と混同しないよう出典欄へ表示します。

### DCXの表示粒度

未公開プレビューでは、LAlert・JAlert・MTInfo・OutsideJapanを次の順で自動選択します。
手動設定や新しいURLパラメーターは不要です。投稿本文は全文を保持します。

1. **地点・範囲**：受信した主楕円と、明示された災害中心位置を表示します。
2. **対象区域**：有効な行政区域指定がある場合、都道府県・市町村の区域を表示します。
3. **トピック**：地理情報が未対応・不完全・投影不能なら、災害種別と通報区分を短く示します。

根拠は [IS-QZSS-DCX-004](https://qzss.go.jp/en/technical/download/pdf/ps-is-qzss/is-qzss-dcx-004.pdf)
の4.2.4節・5節です。楕円はWGS84楕円体面・中心原点のENU座標で定義された通報対象範囲で、
被害範囲ではありません。方位角は東を0度として北へ正方向です。
`preview_dcx_geometry.py` はこの座標変換から境界を求め、緯経度上の単純な楕円には置き換えません。
主楕円の中心を災害発生地点のピンとして表示せず、B2で送られた災害中心位置だけを地点表示します。

国内は確認できたVn=1・B1の精細化を対象とします。国外の共通CAMFはB1・B2の中心位置・
B3第2楕円（個別指示・避難先）・地理情報を追加しない既知のB4に対応します。
国内Vn=0は[互換性調査](../docs/dcx-vn-compatibility.md)済みです。公開仕様は初版から国内の非NULL通報を
Vn=1固定とし、公式の試験原本にあるVn=0を旧仕様として受け入れる根拠は確認できていません。
国内Vn=0の互換性、B4地震の追加震央は未対応のため、
一部の範囲だけを描かず次の有効な候補へ進みます。国外Vnは発信者固有の拡張版なので、
拡張を解釈せず共通CAMFの範囲を表示します。

EX1は主楕円が全0の場合だけ行政区域の指定として採用します。楕円を描けない場合に、
その通報のEX1を代わりの市全域と解釈することはありません。
JAlertはEX8/EX9の全指定を確認します。JISコードを固定アセットのコードへ対応させ、
未収録の区を市全体へ広げる、未知の区域だけ省く、地名から座標を推定するといった補完は行いません。
全polygon・離島を保持し、海外のミニマップにはその周辺地域を表示します。
All Clearは解除として表示し、取消や安全宣言には変換しません。

`preview_dcx_reports.py` が候補を検証し、`preview_wide_dcx.py` が各候補の描画失敗時も含めて
全体を消去して次の段階へ切り替えます。地図・トピックとも長い指示文は投稿本文で読みます。
ギャラリーには元の4受信例に加え、`dcx-ellipse`・`dcx-municipality`・`dcx-prefectures`・
`dcx-ward`（札幌市中央区）・`dcx-wards`（中央区と北区）を収録しています。
後者5件はVnや区域フィールドを変更してCRCを再計算した**合成訓練例**であり、
受信原本と区別して変更内容・元ファイル・チェックサムを記録します。

国外B3は[CAMF 1.2の定義と対応範囲](../docs/dcx-b3-support.md)を確認し、
主範囲を水色の実線・第2範囲を薄紫の破線・避難先の指定を黄色の破線で表示します。
重複区域は主範囲の指示が優先します。
第2輪郭まで全体が描けないときは、主範囲だけの地図を残しません。
指示ライブラリはA9=0/A10=0、C10=0〜16・30・31を対象とします。
C10=0の避難先には主範囲向けの既定指示IC-A-03を投稿本文に補足します。
元のA11指示とNMEAは保持し、訓練・解除を先頭に明示します。本文は画像の有無や投影に依存しません。
国内LAlert・MTInfoは仕様でB1固定のため、B2/B3/B4の幾何情報を表示しません。
`dcx-secondary-ellipse`・`dcx-secondary-overlap`・`dcx-secondary-evacuation`・`dcx-evacuation-overlap`は、
既存の国外受信例から派生した**合成訓練例**です。移動・回転、同心拡大、避難先特例の
表示を確認でき、国・主楕円・国外Vnは元の値を保持しています。
避難先やMTInfoの追加指示を補足する単電文例には、実際の投稿formatterで作る「投稿本文」欄も表示します。
従来の「電文のテキスト」は復号結果として残し、複数電文を集約した投稿とは区別します。

国外B4地震は[受信値と位置解釈を調査](../docs/dcx-b4-support.md)しました。
確認済みの国際ライブラリA9=0/A10=0で、D1〜D4の生値・A18・復号値の整合を検証します。
D3=D4=0も主半長軸の0.25倍の位置指定であり、震央の省略として扱いません。
方位の基準方向と地表上への変換規則は確認できていないため、主楕円だけの地図を残さず、
理由を記録してトピックへ戻します。`dcx-earthquake-vector`はこの動作を確認する合成訓練例です。
地表の震央と深さを持つ震源は区別し、送られていない深さや最大震度を補いません。

MTInfoの[追加避難範囲](../docs/dcx-mtinfo-support.md)は、国内Vn=1・B1・A9=1/A10=0に対応します。
EX2=0は範囲から離れる指示、1は範囲へ向かう指示として、通知対象の実線と追加楕円の破線を
区別します。追加楕円は独立した中心のENU座標で描き、通知対象がEX1の市町村ならその全境界と
併せて表示します。追加楕円の投影失敗や市町村境界の欠落時は、片方だけの地図を残しません。
A11と追加指示は併せて参照し、B3の主範囲優先規則やIC-A-03は適用しません。
本文には訓練・解除を明示して指示と楕円の受信値を補足し、元の全文・A11・NMEAを保持します。
EX2〜EX7が全部0の場合だけ追加指示なしとし、デコーダーが無視するEX2単独1の既知例外は
生値から復元します。画像なし・投影不能でも適合する追加指示は本文に残ります。
`dcx-mtinfo-leave`・`dcx-mtinfo-head`・`dcx-mtinfo-area`は公開アーカイブ由来の合成訓練例です。

### 震度マーカーの調査と表示範囲

2026-11-10にUNNERVの[震度速報](https://unnerv.jp/@UN_NERV/117576014620528706)、
[各地域の震度情報（震度5強）](https://unnerv.jp/@UN_NERV/117576024463380705)、
[震度4の例](https://unnerv.jp/@UN_NERV/117578336376313563)を確認しました。
地図上の色付き四角と大きな震度、地図の弱／強を `− / ＋` で表す方式を参考にしています。
背景・見出し・右欄・ミニマップの位置はShirasuで固定した共通配置を使います。

QZQSMは[IS-QZSS-DCR-017 §4.1.2.3.4、表4.1.2-13〜16](https://qzss.go.jp/en/technical/download/pdf/ps-is-qzss/is-qzss-dcr-017.pdf)
の都道府県コードと震度の組です。元となる情報はJMA XMLの `Pref/MaxInt` で、観測点の位置は含みません。
記号は県の代表位置に置き、震源・観測点の位置や県全体の震度分布を推定しません。
「4未満」は既発表値の修正を表す区分なので、震度3などに読み替えません。
同じ県の異なる受信値は隣接する記号と右欄の各震度群に全て残します。同じ値の重複だけをまとめます。
記号を読みやすく配置できない場合は受信束全体の要旨表示に戻し、県や値を間引きません。
配色は未公開プレビュー内に置き、公開済み画像の配色定義を変更しません。

### 地図の県境と位置表示

未公開プレビューでは洪水・降灰に加え、台風・震源・火山・気象・緊急地震速報・海上警報・震度・津波・
北西太平洋津波の主図にも、薄い県境と必要に応じた右下のミニマップを使います。
主図の県境は日本の原典から抽出した背景の補助線で、危険度を示す線とは区別します。
ミニマップは地形・海岸線の底図に主図の表示範囲を白枠で示す位置案内です。
行政界・対象区域・警報色・河川・中心位置・進路・緯経線は描かず、全国・広域の図には小図を重複して加えません。
海外の予測地点や日付変更線をまたぐ図でも、同じ経度の扱いで表示位置を示します。

主図の区域データは離島を含む全形状を保持し、ミニマップの表示範囲もその全域を含めます。
ミニマップに対象区域の輪郭や着色は加えず、受信した区域名・値は右欄に保持します。
河川・中心位置・対象区域・ラベル・引き出し線が小図で隠れない配置を使い、
情報を保った読みやすい配置を作れない場合は受信束全体の要旨へ戻します。
新しい描画は `--preview` のみで、公開済みv1〜v4のPNG・URL・固定アセットは維持します。

### 降灰予報のプレビュー

```sh
/tmp/shirasu-images-venv/bin/python -m image_service --preview \
  --records image_service/examples/ash_fall.json --output /tmp/ash-preview.png
```

QZQSMの降灰予報（速報／詳細）に含まれる火山・基点時刻・市町村・基点から1〜6時間・
現象を表示します。同じ市町村の異なる時間や、降灰と小さな噴石が同時に含まれる場合も残します。
「基点＋N時間」という通報の時間値を保持し、開始時刻や予報期間の境界を推定しません。
基点時刻と発表時刻はJSTで区別して表示します。
右欄の時間別マスは各受信値を個別に示し、欠けた時間を隣接する値で埋めません。
降灰と小さな噴石が同じ時間に含まれる場合は、両方の段に表示します。

現象ごとのラベルは[気象庁の降灰予報の説明](https://www.jma.go.jp/jma/kishou/know/kazan/qvaf/qvaf_guide.html)
の色分けに合わせ、少量は灰色、やや多量は黄、多量は赤。小さな噴石は独立した赤枠にします。
市町村の輪郭は中立色とし、市町村全域の降灰分布・噴石の落下範囲とは区別します。
火山には公式代表位置の三角印を付けます。噴煙形状、風向き、灰や噴石の軌道は描きません。
阿蘇など内陸の小さな区域だけで過度に拡大されないよう、主図には周囲の海岸が分かる余裕を持たせます。
この縮尺調整には他のQZQSM画像と共通の `preview_scale.py` を使用します。

地理データは[気象庁の市町村等（火山関係）GIS](https://www.data.jma.go.jp/developer/gis.html)の
1745区域をDCRコード・名称と直接照合しています。「その他の市町村」47コードには区域を割り当てません。
全polygon・穴を保持し、簡略化の面積差を1%以内に収めます。
離島を含む全形状を主図のデータに残し、小図の表示範囲にも含めます。小図には市町村の輪郭を描きません。
出典・ハッシュ・除外した地物・加工統計は `assets/preview/municipalities_manifest.json` に記録。
`scripts/prepare_municipality_assets.py` で再生成できます。GIS用の依存は加工専用環境だけに必要です。

取消、未知の値、基点や火山の不一致、同じ市町村・時間の矛盾する降灰量、地図や読みやすい配置が
不足する場合は、受信束全体を共通配置の要旨画像へ渡します。サンプルは桜島の合成訓練通報です。

### 指定河川洪水予報のプレビュー

流路データの加工用依存は受信機や描画サービスへ追加せず、準備専用の環境で使います。
既存の画像用依存に含まれる `azarashi==0.17.1` と、次のハッシュ固定した `pyshp` が必要です。

```sh
python3.12 -m venv /tmp/shirasu-flood-assets
/tmp/shirasu-flood-assets/bin/pip install --require-hashes -r image_service/requirements.txt
/tmp/shirasu-flood-assets/bin/pip install --require-hashes -r scripts/requirements-flood-assets.txt
/tmp/shirasu-flood-assets/bin/python scripts/prepare_flood_assets.py
/tmp/shirasu-images-venv/bin/python -m image_service --preview \
  --records image_service/examples/flood.json --output /tmp/flood-preview.png
```

準備スクリプトは[気象庁提供の固定流路データ](https://www.jmbsc.or.jp/jp/online/c-onlineGsd-oshirase.html#date20260520)
の2026年5月20日版を取得し、SHA-256とDCRのコード表を検証します。保存済みZIPを使う場合は
`--source /path/to/flow.zip` を指定できます。ダウンロードやGIS処理は準備時だけに行い、描画時には外部通信しません。

指定河川洪水予報用の338区間を12桁の予報区域コードで直接対応させ、先頭の0と全ての分岐・区間を保持します。
関連市町村の面、川全体、浸水想定区域には置き換えません。「その他の河川」57コードには位置を割り当てません。
原典は国土数値情報を気象庁が加工した表示用の流路で、現在の川岸や浸水範囲を精密に示すものではありません。
主図の背景には気象庁の都道府県データから抽出した県境を薄く重ね、右下の日本周辺図に主図の表示範囲を白枠で示します。
県境は位置を把握するための補助線です。ミニマップは地形・海岸線と白枠だけにし、河川や県境は重ねません。
主図の河川・ラベル・引き出し線がミニマップで隠れない余白を確保します。
県境は原典の隣接県が共有する線を抽出してから一度だけ簡略化し、`assets/preview/prefecture_boundaries_manifest.json`
に出典・ハッシュを記録します。再生成は `scripts/prepare_prefecture_boundary_assets.py`（加工専用のPyshp・Shapely環境）を使います。

氾濫警戒情報は赤、氾濫危険情報は紫、氾濫発生情報は黒とし、黒い線には明るい縁取りを付けます。
通報の名称を保持し、DCRの内部番号を避難の警戒レベルとして表示しません。
警報解除は中立色の破線と明示的なラベルで示し、氾濫注意情報への切替を含むため安全宣言とは扱いません。
訓練・試験・訂正を明記し、取消、未知の区間・値、同一区間で矛盾する値、流路を共有する区間で異なる情報、読める配置を作れない場合は
受信束全体を共通配置の要旨表示へ戻します。サンプルは合成した訓練通報で、実際の災害情報ではありません。

`assets/preview/flood_manifest.json` と `FLOOD_NOTICE.txt` に出典・入力と加工後のハッシュ・加工内容を記録します。
ZIP固有の再配布条件は公開資料で確定できていないため、生成する `flood.geojson.zlib` はGit対象外です。
ローカル／サービス内部の描画に使い、GIS自体を公開配布する機能は設けません。
PNGには国土数値情報・気象庁の加工とShirasuによる画像作成を明記します。

## v2 の地域別表示

v1の描画をそのまま残し、新しく発行するv2 URLで次の3種類を地図化します。

- 海上警報: 気象庁の地方海上予報区を塗り、区域名と受信した警報を併記します。
  同じ海域の着氷・霧・風などは省略せず、解除は別の色と文字で表示します。
- 震度情報: 都道府県の輪郭と代表位置に受信震度を示します。県全体を同じ震度で
  塗ることはしません。同じ県で複数値を受信した場合は全て併記し、色だけ最大の受信値にします。
  離島が遠く離れている場合は主図を拡大し、離島を含む全域を地図内の小図で補います。
- 津波情報: 津波予報区の沿岸を強調し、予想高と到達予想時刻・状態を表示します。
  浸水範囲や津波の伝播は描きません。解除通報の欠測代用の午前0時は、
  [みちびきの公式通知](https://qzss.go.jp/info/information/dcr_260428.html)に従って時刻として表示しません。

色のない地域は「安全」「警報なし」「揺れなし」を意味しません。画像内にもこの
読み方を明記します。訓練・訂正・取消を区別し、未知の区域、矛盾する区域の重なり、
ラベルや防災上の留意事項が収まらない場合は、通報全体の要旨に戻します。
地域を一部だけ落として地図を完成させることはありません。

区域は [気象庁のGISデータ](https://www.data.jma.go.jp/developer/gis.html) と公式地図の
表示用GeoJSONを固定しています。`assets/v2/manifest.json` に出典・加工方法・ハッシュ、
`JMA_NOTICE.txt` に利用条件と出典表記があります。海域・津波予報区の集約コードは
`groups.json` で基本区域に明示的に展開し、地名のあいまいな一致は使いません。

```sh
/tmp/shirasu-images-venv/bin/python -m image_service --version v2 --records image_service/examples/marine.json --output /tmp/marine.png
/tmp/shirasu-images-venv/bin/python -m image_service --version v2 --records image_service/examples/seismic_intensity.json --output /tmp/intensity.png
/tmp/shirasu-images-venv/bin/python -m image_service --version v2 --records image_service/examples/tsunami.json --output /tmp/tsunami.png
```

海上サンプルは過去の公開通報です。震度・津波サンプルは、分類を訓練に設定した合成通報で、
実際の災害情報ではありません。これらのコマンドは投稿を行いません。

`SHIRASU_IMAGE_KEYS` を設定して `python -m image_service --serve` を実行すると
`127.0.0.1:8080` で WSGI サーバーが起動します。このサーバーはローカル確認用です。
署名鍵は Nostr の鍵とは別の暗号学的乱数 32 バイトを使い、環境変数には次の形で設定します。
実際の秘密鍵をリポジトリ、URL、ログに記録しないでください。

```text
{"k1":"<32 bytes encoded as 64 hexadecimal characters>"}
```

## v3 の予報区域・火山表示

v1/v2 の表示を保ち、v3 URL で次を追加します。

- 気象: 府県予報区の輪郭と受信した警報・情報を表示します。北海道・東京/伊豆・
  鹿児島/奄美・沖縄の細分を都道府県全体へ置き換えません。共通の発表/解除を区別し、
  「全ての気象特別警報」は仕様どおり解除の場合だけ扱います。
- 緊急地震速報: 受信した警報対象区域と、通報全体に1組の予測震度範囲を表示します。
  各区域に固有の震度を割り当てず、震央地名から座標を推定しません。長周期の予測、
  発生時刻、深さ・M、防災上の留意事項を保持します。PLUMの仮定震源はその旨を明記し、
  固定の深さ・Mを実際の地震値として示しません。
- 火山: 気象庁の公式代表位置に印を付け、受信した警戒レベル・現象・活動時刻・
  対象市町村を併記します。「噴火」と「噴火したもよう」、時刻の曖昧さを保持します。
  危険半径、火口の広がり、避難対象区域は推定しません。

地図の輪郭は通報が指す予報区域です。区域全体が一様な危険域であるとは限らず、
未掲載地域の安全も意味しません。離島を含む全範囲を保持し、必要に応じて小図を使います。
未知・矛盾する入力や読める配置を作れない場合は、通報全体の要旨に戻します。

地域データは `assets/v3/regional_manifest.json`、火山位置は `volcano_manifest.json`、
v3専用のNatural Earth 10m底図は `land_manifest.json` に出典・入力ハッシュ・加工条件を
記録しています。大きなGeoJSONはzlib圧縮で同梱し、
実行時にハッシュと展開上限を検証します。外部の地図をリクエスト時に取得しません。
再生成は `scripts/prepare_v3_region_assets.py`、`scripts/prepare_volcano_assets.py`、
`scripts/prepare_v3_land_assets.py` を使います。

```sh
/tmp/shirasu-images-venv/bin/python -m image_service --version v3 --records image_service/examples/weather.json --output /tmp/weather.png
/tmp/shirasu-images-venv/bin/python -m image_service --version v3 --records image_service/examples/eew.json --output /tmp/eew.png
/tmp/shirasu-images-venv/bin/python -m image_service --version v3 --records image_service/examples/volcano.json --output /tmp/volcano.png
```

v3 のサンプルは全て訓練分類の合成通報で、実際の災害情報ではありません。投稿は行いません。

## v4 の気象配色

地域名・代表点は白、予報区の輪郭は灰色のまま、各情報の名称を独立したラベルで表示します。
同じ地域の複数情報を一つの代表色にまとめません。

| 受信情報 | ラベル |
| --- | --- |
| 気象特別警報（DCRコード1〜6） | 黒 `#0c000c` 地・白字・白枠 |
| 土砂災害警戒情報（23） | 紫 `#aa00aa` 地・白字 |
| 記録的短時間大雨情報（21）・竜巻注意情報（22） | 塗りなし・白字・白枠 |
| 解除 | 塗りなし・灰色の字と枠、各情報名に「（解除）」 |

黒・紫は[気象庁の配色指針（表1-1）](https://www.jma.go.jp/jma/kishou/info/colorguide/HPColorGuide_202007.pdf)
によります。21・22の情報そのものの固定色は同指針にないため、名称で区別します。
塗りなしは危険度が低いことを意味しません。竜巻注意情報を通常の注意報と同一視せず、
通報にない警戒レベルや新体系の警報名称も補いません。
解除は個々の受信情報に対するもので、地域全体の安全や「発表なし」を表しません。

パディングと枠を含むラベル寸法で配置を計算し、読める配置を作れない場合は全体を要旨に戻します。
v1〜v3の描画・固定アセットは変更せず、気象以外のv4画像はv3と同じPNGを返します。

```sh
/tmp/shirasu-images-venv/bin/python -m image_service --version v4 --records image_service/examples/weather.json --output /tmp/weather-v4.png
```

## デプロイと HTTP 契約

デプロイパッケージには `image_service/` と共通の `image_protocol.py` が必要です。
Vercel の `api/image.py` から `from image_service.app import app` で WSGI アプリを公開し、
ルートのすべてのリクエストをこの関数へ rewrite します。受信機の `config.py`、SQLite、
バックアップ、秘密鍵をパッケージに含めないでください。

- `GET /healthz`: 鍵設定とv1〜v4全ての固定アセットを検査します。成功は `200`、設定不備は `503`。
- `GET` / `HEAD` の署名付きパス: 成功は `image/png`、PNG 内容の SHA-256 を ETag に使用。
  `Cache-Control: public, max-age=31536000, immutable` と
  `Vercel-CDN-Cache-Control: public, max-age=31536000` を返します。
- `If-None-Match` が ETag と一致する場合は `304`。Cookie・認証ヘッダーは不要です。
- query は拒否します。署名不正は `403`、署名済みでも復号できない通報は `400`、
  レンダラーの不備は `503`。エラーと health は `no-store` です。

HMAC は新しい入力の作成を制限する仕組みです。公開済みの URL は誰でも繰り返し取得でき、
有効期限はありません。鍵をローテーションするときは新しい key-id を追加し、古い投稿を
維持する期間は古い検証鍵も残します。署名 URL は入力内容を暗号化するものではありません。

## 再現性とアセット

`assets/v1/` の Natural Earth 50m land、Noto Sans CJK JP Regular / Bold は固定コピーです。
出典・SHA-256 は `manifest.json`、ライセンスは `NATURAL_EARTH.txt`、`OFL.txt`、
`FONT_NOTICE.txt` にあります。実行時にハッシュを検証します。外部の地図・フォントを
取得しないので、表示される地形や字形は外部サービスの更新に影響されません。
日本語の地名を欠落させないためフォントを部分化していません。v1 のアセットは約 35 MB です。

公開後に v1 の見た目、デコード規則、依存、アセットを変更すると同じ URL の内容が変わります。
v2・v3・v4も公開後の出力を維持します。既存PNGが変わらない修正では版を上げません。
新しい種類の画像やデザイン調整は未公開の作業版とプレビューでまとめ、公開の区切りで
必要な場合だけ新しい描画経路を追加します。古い経路と検証鍵は残してください。
運用方針は [キャッシュと世代管理](../IMAGES.md#キャッシュと世代管理) を参照してください。
Matplotlib の描画と azarashi の multipart 組立状態はリクエスト全体のロックで保護し、
各リクエストの前後で組立状態を破棄します。
